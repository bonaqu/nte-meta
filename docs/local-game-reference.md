# Локальный справочник NTE

В админке добавлен раздел **Данные игры**: поиск по RU/EN/JA/ZH и ключу, фильтр по типу и игровому ID персонажа, редактирование переводов, JSON-полей и изображений. Кнопка «Сохранить в базу» сразу записывает правку в D1. Сохранённые значения доступны после перезагрузки и используются при следующем импорте/переводе.

Исходные значения и ручные изменения хранятся отдельно. Изменение русского имени не замораживает остальные языки. Повторный импорт обновляет исходные поля, сохраняя ручные правки. Устаревший редактор получает конфликт 409. «Восстановить данные игры» убирает ручные изменения выбранной записи.

## Извлечённый снимок

- 113 016 уникальных ключей локализации, четыре языка: ru/en/ja/zh-Hans.
- 286 таблиц: персонажи, биографии, навыки, параметры и модификаторы, дуги, экипировка, гардероб, симпатия и подарки, предметы.
- 7 508 уникальных изображений: 7 511 извлечённых текстур с тремя различающимися регистром алиасами. Иконки подготовлены в WebP до 512 px, крупные арты — до 1 800 px. Исходные текстуры остаются в локальном каталоге экспорта.
- Всего 195 522 записи, включая локализацию интерфейса, справочные строки, числовые таблицы и изображения. Это число записей, а не количество персонажей или предметов.
- 1 024 блока источника в D1. Полный текст индексируется по блокам; отдельные записи возвращаются с пагинацией. База SQLite со снимком занимает около 269 МБ. Сжатый снимок хранится в `scripts/content/game-data/chunks.jsonl.gz`, изображения — в `public/game-assets/`.

Базовые архивы и PatchPaks читаются вместе. Для каждой локали сначала учитывается базовая выгрузка, затем `_0_P`. Связи строятся по ключам StringTable, ID строк DataTable и ID персонажа. Например, `ST_Player::Role_Name_025` связывает **Хатор / Hathor / ハソール / 哈索尔**, игровой ID `1025`.

Справочник подключён к «Найти базовую информацию», поиску дуг/картриджей и предложениям импорта гайдов. Перевод публикаций защищает найденные игровые названия от машинного перевода и восстанавливает русские значения из базы. Неоднозначные соответствия не подменяются автоматически. Изменение текста в справочнике само по себе не публикует и не переписывает готовые гайды.

## Границы данных

34 таблицы в читаемых пакетах содержат ноль строк, в том числе `DT_Character`, `DT_ItemConfig`, `DT_ForkItemData`, `DT_CharacterAbilityConfig`, `DT_LikeabilityRoleData`. Их полный перечень находится в `manifest.json`. Наличие названия предмета и его иконки не доказывает наличие всех связей с материалами, источниками получения или подарками.

Часть строк содержит параметры `{0}`, `{1}` для подстановки уровня/эффекта во время игры. Они сохранены в исходном справочнике. Импорт персонажа предлагает только описания навыков без неразрешённых параметров; иконки предлагаются отдельно. Поиск экипировки не выдумывает численные параметры отсутствующей таблицы. Нужные уровни, коэффициенты и недостающие связи по-прежнему проверяются по доступным таблицам/внешним источникам или заполняются администратором.

## Повторное извлечение

Локальная игра не изменяется. Инструмент не запускает игру, не внедряется в процесс и не использует античит-обходы. В отдельном каталоге создаются ссылки на архивы; ключ архивов и `.usmap` остаются вне Git. RuntimeData с видеоданными не копируется.

Используется [UEExtractor 1.0.8.7](https://github.com/SolicenTEAM/UEExtractor/releases/tag/v.1.0.8.7) с CUE4Parse и существующим .NET 10. Путь на этой машине: `D:\CODEX\Programs\UEExtractor\1.0.8.7`. ZIP SHA256: `E89FFECE53CC11970D08F6D0A683B67CA58882E8C51FB99DE07923175EB96660`. Для нормализации подходит установленный `D:\CODEX\Programs\Python312\python.exe` с Pillow.

```powershell
./scripts/game-data/extract-local.ps1 -Mapping <актуальный.usmap> -ArchiveKeyFile <локальный_файл_ключа>
# Скрипт напечатает новый каталог выгрузки.
& D:/CODEX/Programs/Python312/python.exe scripts/game-data/normalize.py --source <каталог_выгрузки> --repository D:/Projects/nte-hub
& D:/CODEX/Programs/Python312/python.exe scripts/game-data/validate.py --database <новый_файл_проверки.sqlite>
node scripts/game-data/verify-reference.mjs --database <новый_файл_проверки.sqlite>
```

После проверки новый снимок и изображения публикуются через Issue/PR/Actions. Workflow **Deploy Cloudflare Worker** применяет схему, публикует API и импортирует снимок существующим Cloudflare-токеном из GitHub Secrets. В браузере токена нет. Уже импортированный SHA256 пропускается; повторная запись неизменившихся блоков не выполняется. Во время пакетного импорта индекс пересобирается один раз, затем его триггеры восстанавливаются, включая обработку ошибки. Действия администраторов хранятся в отдельной таблице и не удаляются.

Cloudflare не может читать `D:\Games` напрямую: после обновления клиента локальную выгрузку нужно повторить. Изменение базы через админку не требует Git-коммита или новой сборки сайта.
