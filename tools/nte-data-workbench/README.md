# NTE Meta — редакция и игровые данные

Запуск на этом компьютере: дважды нажмите **Start.cmd**. Программа использует общий Python из `D:\CODEX\Programs\Python312`, UEExtractor, .NET и FFmpeg; копировать их в папку игры не нужно.

## Управление сайтом

В одном окне доступны новости и слухи, гайды, персонажи с биографиями, тир-листы и общая база игры. Откройте «Мой профиль» и войдите под своей учётной записью: доступны те же права и редакторы, что на сайте. Можно создавать и изменять материалы, принимать предложения импорта и публиковать их обычными кнопками редактора. Нужен интернет. Вход в программу отдельный от обычного браузера; копирования чужих cookies нет.

Кэш, профиль встроенного браузера и новые временные файлы находятся в `E:\CODEX - IMPORT HERE TEMP FILES AND OTHER\nte-meta\desktop`. Существующие настройки выгрузки сохранены. Для интерфейса переиспользуется установленный PySide6; зависимости отдельного компьютера перечислены в `requirements-desktop.txt`.

«Данные установленной игры» проверяет патч при запуске. Действия извлечения и экспорта открывают прежнее рабочее окно с параметрами, подсказками и журналом; закрытие редакции не прерывает извлечение. Веб-странице не предоставляется Python-мост, доступ к ключам или запуск локальных команд.

При временном сбое открытия архивов программа делает до трёх попыток. Другие ошибки не повторяются автоматически. Неудачная выгрузка не выбирается для публикации; предыдущий рабочий снимок сохраняется. Сообщение UEExtractor об отсутствии файлов само по себе не означает, что нужен новый ключ. При повторном сбое сначала дождитесь завершения загрузок в лаунчере и проверьте журнал.

## После обновления игры

1. Закройте игру и дождитесь окончания обновления в лаунчере.
2. Откройте программу. Проверьте папку игры, UEExtractor, `.usmap` и путь к файлу ключа архивов. Текущие рабочие пути уже подставлены; ключ не показывается в окне и не сохраняется в Git.
3. Нажмите **Извлечь обновление**. Если архивы не изменились, программа предложит использовать готовую выгрузку. После патча новая версия появится в той же указанной папке, в отдельном подкаталоге с датой; старая сохранится. Совпадающие таблицы, текстуры, локализация и WEM после проверки SHA-256 переиспользуются жёсткими ссылками, изменённые остаются отдельными версиями. Повторное чтение изменившихся архивов нужно для проверки данных; интернет для извлечения не используется. Поле «Рабочая выгрузка» переключится на новый снимок.
4. При необходимости нажмите **2 · Обновить дополнение**. Это отдельная сетевая операция: Nanoka дополняет материалы и дуги, Kaiden — награды симпатии, Neverness.app — подарки. Происхождение записей сохраняется; данные не выдаются за извлечённые из игры.
5. Нажмите **3 · Подготовить снимок игры**. Будут созданы снимок справочника, WebP, Opus и проверенная SQLite-копия. Обработка аудио при первом запуске занимает больше времени; готовые файлы используются повторно.
6. Нажмите **4 · Каталог игрока / Excel / MP3** и выберите родительскую папку. Программа создаст новый каталог `NTE-дата-время`, не перезаписывая прошлый экспорт. Нажмите **Открыть каталог игрока**: откроется `Для игрока/Начать здесь.html`. Для технической работы также остаются `Открыть отчёт.html` и полный Excel.

Извлечение читает архивы через ссылки во внешней рабочей папке. Оно не меняет установку игры. Не запускайте извлечение одновременно с обновлением: ссылки относятся к текущим архивам, а не к их резервной копии.

## Каталог для обычного игрока

Начальная страница — **`Для игрока/Начать здесь.html`**. Для просмотра интернет не нужен. Все имена и описания берутся из подтверждённых связей клиента; отсутствующие подписи не придумываются.

- **Персонажи:** отдельное JSON-досье и девять страниц: биография с паспортом и актёрами, начальные характеристики, навыки по типам с таблицами уровней, шесть пробуждений и резонансы 3/6, возвышения с материалами и опытом, уровни симпатии и любимые подарки, гардероб, озвучка по языкам, игровые рекомендации дуг/статов/уровней навыков.
- **Экипировка:** дуги, картриджи и консоли. Доступные эффекты и характеристики, значения дуг по уровням, материалы возвышения.
- **Предметы:** категории по назначению, включая опыт персонажа/дуги/модулей, материалы возвышения, еду, подарки, валюты, мебель, транспорт, задания и коллекции.
- **Медиатека:** все извлечённые изображения в PNG, группы по назначению, по 100 изображений на странице. Если название или владелец не подтверждены, остаются изображение и исходный путь в раскрываемом блоке.
- **Реплики:** MP3 с названием игровой ситуации, папки персонажей и языков; текст реплики рядом с проигрывателем. Дополнительные и старые игровые ID вынесены в «Архив озвучки». Неизвестная ситуация явно подписана как неизвестная.
- **Понятный Excel:** `Для игрока/NTE — для игрока.xlsx`, русские заголовки, отдельные листы для навыков, параметров, пробуждений, возвышений, подарков, гардероба и реплик. Фильтры и ссылки на досье/MP3.

**WEM — рабочий формат игры.** Папка вида `дата/export/audio/English` содержит исходные `.wem`, а не WAV/MP3 для обычного проигрывателя. Чтобы получить готовую озвучку, выполните шаг 3, затем 4 с включёнными медиа. Кнопка **Открыть рабочую папку** открывает исходники; **Открыть каталог игрока** открывает готовый результат. Подсказки доступны при наведении на каждое поле и кнопку, а также при переходе клавишей Tab.

Первое создание досье занимает больше времени: используется тот же обработчик таблиц, что и на сайте. Результат кешируется по хешу снимка и кода обработчика; после обновления данных кеш строится заново. Экспорт PNG/MP3 требует больше места, чем сжатые WebP/Opus сайта. Переключатель медиа позволяет получить только текст и таблицы.

## Полные технические данные

- **Excel:** листы по категориям, ID, владелец, таблица, RU/EN/JA/ZH, ссылки на медиа и исходные поля. Используйте фильтры Excel; длинные поля указывают на полную строку JSONL.
- **Категории:** CSV с UTF-8 BOM и полные JSONL. Строки не обрезаются в единственной копии данных.
- **Персонажи:** папка `игровой ID — имя`, отдельные разделы и собственная папка медиа. Общие записи без доказанной связи с персонажем остаются в общих категориях.
- **Медиа:** изображения и реплики. В папках персонажей создаются жёсткие ссылки на центральные файлы, где файловая система это поддерживает; иначе — копии.
- **manifest.json:** счётчики, хеш снимка, ошибки и список пустых таблиц. `namespace`, `gameId`, `details.references` и `assets.path` помогают проследить исходную связь.

Старые ID и действующие персонажи сохраняются отдельно. Категория — подсказка; точное назначение задают исходная таблица и связи. Внешние дополнения отмечены в `details.reference`.

## Публикация на сайте

При запуске и по кнопке **5 · Проверить обновления** программа сравнивает игровые архивы с рабочей выгрузкой. Если изменились архивы или голосовой пакет, выполните шаги 1 и 3. Незавершённый снимок нельзя использовать для подготовки.

**6 · Персонажи для сайта** сверяет проверенный снимок с каталогом сайта. Создаётся файл `Персонажи для сайта.json` для новых персонажей и миграция обновления существующих профилей, которая сохраняет ручные тексты и загруженные администратором изображения. Повторная подготовка использует ту же ещё не опубликованную миграцию.

**7 · Создать PR данных** создаёт Issue и pull request с игровым справочником, медиа и обновлением профилей. Нужны вход в GitHub CLI, актуальная основная ветка и отсутствие посторонних изменений. Кнопка не объединяет PR: откройте ссылку из журнала, проверьте изменения, дождитесь проверок и объедините его на GitHub. GitHub Actions опубликует сайт, применит миграции и импортирует справочник в D1. Ручные правки справочника хранятся отдельно от снимка.

Для нового персонажа после публикации медиа откройте **Админка → Данные игры → Новые персонажи из локальной программы**, выберите JSON из шага 6, проверьте редкость, атрибут, роль и тип дуги. Нажмите **Создать черновик персонажа**. Существующий персонаж этим действием не перезаписывается. Черновик можно отредактировать и опубликовать из админки.

Сам экспорт Excel ничего не публикует. Он содержит полный снимок, подготовленный последней успешной операцией 3, а не произвольные файлы из поля «Существующая выгрузка».

## Ограничения, которые нужно видеть

Пустая таблица или отсутствующий файл не заменяются вымышленными данными. Читаются все установленные пакеты: английский, японский, китайский и корейский. После обновления пакета штатным лаунчером повторите извлечение. События с нулевым или отсутствующим ID медиа остаются без аудио и попадают в журнал ошибок. Новым персонажам без старой таблицы профиля реплики подбираются только по однозначной игровой связи и точному локализованному названию/тексту.

После патча формат архивов может потребовать обновлённый `.usmap` или ключ. Если чтение завершилось ошибкой, сохраните журнал и предыдущий рабочий снимок; программа не подбирает ключи и не изменяет защиту игры. Журналы UEExtractor могут содержать технические данные ключа — не публикуйте их.

## Командная строка

Владелец реплик определяется по игровому ID строки профиля. Имя файла может содержать старый ID: например, `1009FileDataTable` хранит женский вариант Зеро в строке `1051`. Для проверки этой связи без открытия архивов:

```powershell
dotnet run --project scripts/game-data/extractor -- --profile-voices ПутьКТаблице.json
```

Офлайн-проверка регрессии: задайте `NTE_EXTRACTOR_DLL` равным полному пути к собранному `extractor.dll` и запустите `python -m unittest discover -s tools/nte-data-workbench -p test_voice_bindings.py`.

```powershell
D:\CODEX\Programs\Python312\python.exe -X utf8 tools/nte-data-workbench/exporter.py --repository D:\Projects\nte-hub --output D:\Exports\NTE-new
```

Для экспорта без медиа добавьте `--no-media`. Проверенные Python-зависимости перечислены в `requirements.txt`; программа переиспользует установленные общие библиотеки. Для проверки экспортера: `python -m unittest discover -s tools/nte-data-workbench -p "test_*.py"`.
